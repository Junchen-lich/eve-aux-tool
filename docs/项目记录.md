## 一、项目定位

### 1.1 一句话定位

> **把玩家在游戏里的真实角色状态（技能、资产、钱包、工业任务）拉下来，自动代入官方工业公式，实时算出「做一单赚不赚、每天能做多少」。**

### 1.2 与「市场动态与制造核算台」的分工

两个项目解决的是**同一条价值链上的不同环节**，本项目是后者的**上游与内核**。

| 维度 | 市场动态与制造核算台 | **EVE 辅助工具（本项目）** |
| --- | --- | --- |
| 核心定位 | 行情查询 + 手工核算工具 | **角色数据同步 + 自动核算引擎** |
| 角色数据来源 | 用户手工填 11 项技能 | **官方 ESI 授权拉取，自动同步** |
| 税率算法 | 1.5% × 技能系数（**与官方公式不符**） | 官方绝对值公式（已按 EVEU/CCP 文档校正） |
| 技能效果 | 仅用于费率与时间系数 | 扩展到 ME/TE/槽位/提炼/研究全线 |
| 市场数据 | ceve-market 三前缀 | ESI 官方 + c3q 合同（补 buyout） |
| 服务器 | 三服切换（仅行情层） | 三服**原生**支持（含 SSO 与数据隔离） |
| 数据库 | 无角色绑定 | 内置完整 SDE + 中文名 + 技能表 |
| 用户动作 | 输入数字 → 看结果 | **授权一次 → 自动算** |

**关键定位差异**：旧项目是「计算器」，本项目是「**会自己获取输入的**计算器」。旧项目里技能要手填，填错就错；本项目的技能从游戏服务器同步，天然准确。

### 1.3 目标用户

| 用户 | 场景 | 核心诉求 |
| --- | --- | --- |
| **工业制造者**（主力） | 决定造不造这单、造多少 | 成本/利润精确到 ISK，日产能多少 |
| **搬砖工/ 矿工** | 选星系、算挖矿收益 | 精炼加成、提炼产出一键算 |
| **囤货 / 半工业** | 种菜 + 倒卖 | PI 周期利润、成本指数 |
| **多号玩家** | 一堆角色要分别核算 | 角色档案管理 + 一键切换 |
| **新手** | 不知道自己能不能造 T2 | 技能差距分析 + 缺什么材料 |

#### 关键设计点

1. **三服 SSO 双通道**
   - 欧服：`https://login.eveonline.com/v2/oauth/authorize`
   - 国服（晨曦 + 曙光）：`https://login.evepc.163.com/v2/oauth/authorize`
   - 桌面应用使用 **PKCE**（Authorization Code + PKCE），不硬编码 client secret
   - 令牌有效期 20 分钟，需自动刷新；刷新令牌长期保存

2. **最小 scope 原则**
   默认只申请 `SCOPES_MINIMAL` 六项（技能×2、钱包、资产、工业任务、声望），其余按需在设置里开启——减少授权页阻力。

3. **多角色档案**
   以「角色 ID + 服务器」为主键；每条档案缓存上次同步时间与技能快照；技能变化时给出提示（"你的会计学从 4 级升到 5 级，销售税从 5.30% 降到 4.80%"）。

4. **国服 typeID 映射待建立**（实测发现）
   国服 ESI 的 `universe/ids` **不解析 inventory_types**（实测 POST `[3409,3385,3389]` 返回的是角色名与公司名「华兴商团」），且国服 typeID 体系与欧服不同。→ 需单独建立国服技能 typeID 映射表，或改用「技能英文名」匹配（ESI 已把 `Refining` 改名为 `Reprocessing`，实测 11 个技能名只能解析出 10 个，需修正）。

#### ★ 与旧项目的税率算法差异（重要修正）

官方税率是**绝对值公式**，不是「基础值 × 技能系数」：

```
销售税 = 7.5% − 0.55% × 会计学等级        （5 级 → 4.80%）
经纪费 = 3%   − 0.3%  × 经纪人关系学等级    （5 级 → 1.50%）
```

旧项目用的是 `1.5% × (1 − 0.11×等级)`：

| 会计学等级 | 旧项目算法 | 官方公式 | 偏差 |
| --- | --- | --- | --- |
| 0 | 1.50% | 7.50% | 低估 5.0 倍 |
| 3 | 1.00% | 5.85% | 低估 5.9 倍 |
| 5 | 0.67% | 4.80% | **低估 7.2 倍** |

**这意味着旧项目算出的挂单收益在所有技能等级下都偏高**，尤其 5 级会计学时误差最大。经纪费同理（5 级：旧 1.13% vs 官方 1.50%）。

> 另注：销售税基础值在 **2025-03-12 版本 22.02** 从 4% 上调到 **7.5%**，旧项目的 1.5% 基础值已严重过时。

#### 已实现的计算函数（`src/core/skills.js`，38 项自检全通过）

```javascript
salesTaxRate(skills)                  // 销售税：7.5% − 0.55%/级
brokerFeeRate(skills)                 // 经纪费：3% − 0.3%/级，下限 1%
brokerFeeRateStructure(rate)          // 玩家建筑：业主设定，技能不影响
manufacturingTimeMult(skills)         // (1−0.04×工业理论)(1−0.03×高级工业理论)
researchTimeMult(skills, act)         // ME:科学×冶金；TE:研究；拷贝/发明:科学
manufacturingSlots(skills)            // 1 + 批量生产学 + 高级量产技术
labSlots(skills)                      // 1 + 实验室运作理论
refineYieldBonusPct(skills)           // 3×提炼学概论 + 2×提炼效率理论
materialQuantity(base, meLevel, runs) // ME 减材 + 官方取整规则
timeFactor(teLevel)                   // TE：每级 −2%
manufacturingCost(p)                  // 单流程 / 单件 / 总成本
sellRevenue(p)                        // 挂单收益（毛收/税/费/净/利润/回报率/保本价）
priceForMargin(p)                     // 反解最低卖价（投资回报率口径）
priceForNetMargin(p)                  // 反解最低卖价（毛利率口径）
dailyOutput(p)                        // 日产能
skillEffectSummary(skills)            // UI 展示用汇总
```

#### ME 取整规则（官方，易错）

> 材料需求**向上取整到下一位有效数字**（14.4 → 15）；
> ME 计算**作用于整个 job 而非每 run**；
> 「每 run 需1 个单位」的材料**不受 ME 影响**（如造 10 艘帕拉丁需 10 艘灾难级，不因 ME 减免）。

### 2.6 模块⑤：收益决策

| 编号 | 功能 | 说明 | 优先级 |
| --- | --- | --- | --- |
| F-5.1 | 挂单收益核算 | 毛收 − 销售税 − 经纪费 − 成本 = 利润 | P0 |
| F-5.2 | 投资回报率 / 毛利率 | 双口径展示（避免歧义） | P0 |
| F-5.3 | **保本卖价 / 目标利润卖价反解** | 给定目标利润求最低卖价 | P0 |
| F-5.4 | 日产能估算 | `86400 ÷ 单流程秒数 × 槽数 × 产出数` | P0 |
| F-5.5 | 多候选对比 | 同一物品多个买卖方案横向比 | P1 |
| F-5.6 | **材料缺口诊断** | 用角色资产 + 钱包算出「缺什么、去哪买、差多少钱」 | P1 |
| F-5.7 | 采购清单导出 | 一键复制进游戏批量采购 | P1 |
| F-5.8 | 收益历史回溯 | 用历史成交价回算「当时做这单赚多少」 | P2 |
| F-5.9 | 批量扫描（找最赚钱蓝图） | 遍历市场分组批量核算排序 | P2 |

#### 收益核算公式（已实现并验证）

```
毛收入     = 卖价 × 数量
销售税     = 毛收入 × 销售税率(技能修正)
经纪费     = 毛收入 × 经纪费率(技能修正，玩家建筑则用业主设定值)
净收入     = 毛收入 − 销售税 − 经纪费
利润       = 净收入 − 单件成本 × 数量
投资回报率 = 利润 ÷ 成本          （行业惯例口径）
毛利率     = 利润 ÷ 毛收入
保本卖价   = 单件成本 ÷ (1 − 销售税率 − 经纪费率)
目标价反解 = 单件成本 × (1 + 目标回报率) ÷ (1 − 税率合计)   ← 回报率口径
           = 单件成本 ÷ (1 − 税率合计 − 目标毛利率)        ← 毛利率口径
```

### 4.3 数据流

```

    ▼
```

4. 令牌不应暴露在页面全局

> ★ **重要更正（2026-11-03）**：此前用 curl 探测得出「国服 authorize 只支持 POST（GET 返回 405）」是**误判**。

### 7.2.1 ★ 国服授权链路的三个实测边界（2026-11-03 端到端验证）

**① authorize 阶段完全不校验 redirect_uri**

对同一 client_id 送入五种 redirect_uri，全部被接受并跳转登录页：

| redirect_uri | authorize 阶段结果 |
| --- | --- |
| `http://localhost:8657/sso/callback` | 接受 |
| `https://esi.evepc.163.com/ui/oauth2-redirect.html`（官方） | 接受 |
| `https://evil.example.com/callback`（伪造） | 接受 |
| 空值 | 接受 |
| `not-a-url`（非法格式） | 接受 |

→ 推论：**redirect_uri 的合法性是在登录之后才校验的**，authorize 阶段不拦。
本地回调 `http://localhost:8657/sso/callback` 因此在授权入口处不会被拒，
但最终能否正常回调仍需真实登录后确认（受网易为该公共 client_id 配置的白名单约束）。

**② 浏览器持有失效网易 Cookie 会让 authorize 直接失败**

现象：浏览器访问授权 URL 返回
`{"error":"invalid_request","error_description":"Unable to check RealID binding if user isn't logged in. Missing Netease token."}`

隔离实验（同一 URL、同一请求头）：

| 环境 | 结果 |
| --- | --- |
| curl（无 Cookie） | **正常跳网易登录页** |
| curl（带伪造 Cookie） | 正常跳登录页 |
| 干净 Chrome 独立 profile | **正常跳网易登录页**（`<title>登录</title>`） |
| WorkBuddy 内置浏览器 | **JSON 错误**（缺 Netease token） |

→ 根因：内置浏览器 profile 里残留了失效的网易登录 Cookie，服务端据此判定「用户已登录」，
继而尝试检查 RealID 绑定并失败。**与本工具的请求参数、PKCE、redirect_uri 均无关。**
→ 处置：清除 `login.evepc.163.com` 的 Cookie，或改用系统浏览器 / 无痕窗口。
→ 代码侧已加 `explainAuthError()`，把该英文错误翻译为可操作的中文提示。

**③ 端口回退后回调地址必须同步**

旧实现在端口被占用而自动 +1 时，`auth.redirectUri` 仍指向原端口，
授权码会被回调到占用该端口的**另一个服务**。已修复：监听确定后同步 `redirectUri`。

### 7.3 授权流程

```
1. GET /sso/start?server=serenity&scope=...
      → 生成 code_verifier（32 随机字节）/ code_challenge（S256）/ state
      → 欧服：302 到 login.eveonline.com
      → 国服：返回转发页，表单 POST 到 login.evepc.163.com

2. 用户在 EVE 登录页选择角色并授权
      → 回调 http://localhost:8657/sso/callback?code=...&state=...

3. GET /sso/callback
      → 用 code + code_verifier 换令牌
      → 解析 JWT 的 sub 字段（"CHARACTER:EVE:12345"）得到角色 ID
      → 自动触发 POST /api/sync 同步技能

4. POST /api/sync {serverKey, characterId}
      → 拉取技能 / 属性 / 钱包 / 资产 / 工业任务 / 位置 / 在线状态
      → 写入档案，检测技能变化并返回中文变化提示
```

### 7.4 PKCE 与令牌安全

- **不硬编码 client secret**：桌面应用用 Authorization Code + PKCE（S256），只需公开的 Client ID
- `code_verifier` 每次授权随机生成，`state` 防 CSRF，pending 记录 10 分钟自动清理
- 令牌存 `用户数据/eve_auth_v1.json`（权限 0600），refresh token 长期保存
- 访问令牌 20 分钟过期，剩余 <60 秒时自动刷新（`getValidToken`）
- JWT 只做解析不做验签（仅用于取角色 ID 与名称，不用于鉴权决策）

### 7.5 角色档案

- **前台展示**：`displaySkills()` / `displaySkillGroups()` 输出中文名 + 分组（贸易/生产/提炼/科研），英文名仅保留在数据层

## 八之二、服务端化改造（2026-11-03）

> 目标：服务迁入专用服务器对公众提供。同一份代码通过环境变量切换本地/服务器形态。
> 详细部署说明见 `docs/服务器部署指南.md`。

### 改造前的实测问题（全部经实测确认，非推测）

| 问题 | 实测证据 | 后果 |
| --- | --- | --- |
| 监听 `0.0.0.0` | `netstat` 显示 `0.0.0.0:8657`；局域网 IP `192.168.9.103:8657` 直接返回 200 | 未鉴权即已对局域网暴露 |
| 无任何鉴权 | `/api/profiles`、`/api/config`、`/sso/start`、`/esi/*` 全部裸奔 | 任何人可读角色数据 |
| 数据全局单例 | `ProfileStore` 与 `AuthManager` 各用一个全局 JSON | 多用户互相覆盖、互相可见 |
| 回调地址硬编码 | `server.js` 写死 `http://localhost:PORT/sso/callback` | 换域名即失效 |
| 令牌明文落盘 | `auth.json` 直接存 `access_token` | 文件泄露即令牌失守 |
| 无健康检查 | 无 `/healthz` | 负载均衡无法探活 |
| 无优雅关闭 | 无 SIGTERM 处理 | systemd 停止时中断在途请求 |

### 改造内容

**① 多用户隔离**（`src/core/user-store.js`，76 项测试）

- `userId = SHA256(服务端盐 + 用户名)`，与口令解耦 → 改口令不影响数据目录
- 每用户独立目录：`用户数据/users/<userId>/{meta,auth,profiles}.json`
- 口令 **scrypt**（N=16384）哈希，每用户独立随机盐，不存明文
- 会话 Cookie = `userId.过期时间.HMAC(盐)`，`HttpOnly + SameSite=Lax`
- 原子写入（临时文件 + rename），文件损坏时返回空对象而非崩溃
- 路径穿越防护：`userId` 须匹配 `^u_[0-9a-f]{32}$`
- 旧版单文件自动迁入 `users/local/`，不丢已有数据

**② 鉴权与会话**

- 单用户模式（本地开发，默认）：不校验口令，共用 `local` 空间
- 多用户模式（`EVE_MULTI_USER=1`）：注册 + 登录 + 会话校验
- 登录接口独立处理：表单与 JSON 都支持；错误提示不区分「用户不存在」与「口令错误」（防用户枚举）

**③ 监听与地址外部化**

| 环境变量 | 默认 | 说明 |
| --- | --- | --- |
| `HOST` | `127.0.0.1` | **默认只绑回环**，避免误暴露 |
| `PORT` | `8657` | 占用时 +1 回退，回调地址同步 |
| `BASE_URL` | — | 推导 SSO 回调地址 |
| `EVE_MULTI_USER` | 未设 | 设 `1` 启用多用户 |
| `EVE_SALT` | 自动生成 | 持久化到 `用户数据/server_salt.txt` |
| `TRUST_PROXY` | 未设 | 设 `1` 后按 `X-Forwarded-For` 取真实 IP |
| `SESSION_TTL` | 7 天 | 会话有效期 |

**④ 令牌落盘加密**（`src/core/auth.js`）

多用户模式下用 `AES-256-GCM` 加密，令牌密文存盘：
`{ __enc:"gcm", iv, tag, data }`，密钥由服务端盐派生。
实测：磁盘上无明文令牌；错误密钥与篡改密文均被 GCM 认证拒绝；兼容旧的明文格式。

**⑤ 健康检查与运维**

- `GET /healthz`（公开）→ `{ok, service, version, uptime, users, mode}`
- 访问日志含真实客户端 IP、方法、路径、状态码、耗时
- SIGTERM/SIGINT 优雅关闭（最多等 10 秒）
- 注册频率限制：单 IP 每小时最多 5 个账号（`EVE_MAX_REG_PER_HOUR`）

**⑥ 部署资产**

| 文件 | 用途 |
| --- | --- |
| `deploy/systemd/eve-aux-tool.service` | systemd 服务单元（含沙箱加固、只允许写用户数据目录） |
| `deploy/nginx/eve-aux-tool.conf` | Nginx 反代（TLS、分级限流、安全响应头） |
| `deploy/scripts/deploy.sh` | 一键部署脚本（幂等） |
| `.env.example` | 环境变量模板 |
| `docs/服务器部署指南.md` | 完整部署与运维文档 |

### 实测验证结果

## 十、风险与限制

| 风险 | 等级 | 缓解 |

| **技能效果常量随游戏版本变化** | 高 | 独立成 `data/sde/skills.json`，标注来源与核对日期，版本变化时单点更新（代码从表读，不硬编码） |

| 官方 ESI 错误额度有限（国服仅 50） | 中 | 服务端统一调度 + 本地缓存 + TTL；额度耗尽时降级到缓存数据 |
| ESI 无合同 buyout | 中 | 用 c3q `listContractAll` 补位（三服覆盖） |
| 曙光服 ESI 不区分服 | 中 | 已定位：走 c3q `market-sg`；配置中用 `esiMarketIsShared` 标记 |
| 上游为第三方公益服务 | 中 | 超时重试、缓存优先、失败降级到 EIV 基准价 |
| 蓝图 YAML 解析依赖特定缩进约定 | 低 | 已实测锁定并加断言测试；SDE 换版时需复测 |
| SSO 令牌管理 | 低 | PKCE + 本地加密文件；refresh token 长期保存 |

## 十一、明确不做

| 不做项 | 理由 |
| --- | --- |
| 引入 React/Vue/TypeScript/npm 依赖 | 破坏单文件分发与零依赖优势 |
| 引入数据库（SQLite 等） | 用户数据是少量 JSON，文件系统更可审计 |
| 上云 / 账号体系 | 与本地优先定位冲突；GPL + 云化不兼容商业模式 |
| 移动端 / 小程序 | 用户场景是桌面长时操作，非碎片浏览 |
| 与旧项目代码共享 | **明确要求独立**：避免耦合，双向可演进 |
| 自动挂单 / 自动下单 | 触及游戏 ToS 边界，风险不可控 |
| 价格预测 / 走势预测 | 无可靠数据基础，不做假数据 |
| 前台显示英文名 | 用户要求前台用国服中文；英文仅作回退 |
