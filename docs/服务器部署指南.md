# EVE 辅助工具 —— 服务器部署指南

> 面向「迁入专用服务器、对公众提供服务」的部署形态。
> 与本地开发形态共用同一份代码，通过环境变量切换。

---

## 一、两种运行形态

| | 本地开发 | 服务器部署 |
| --- | --- | --- |
| 监听地址 | `127.0.0.1:8657` | `127.0.0.1:8657`（由 Nginx 反代对外） |
| 用户模式 | 单用户（不校验口令） | **多用户**（注册 + 登录 + 数据隔离） |
| 访问入口 | `http://localhost:8657` | `https://eve.example.com` |
| 静态资源 | 直接由 Node 托管 | Nginx 托管静态、Node 只处理动态 |
| 进程管理 | 手工 `node server.js` | systemd 常驻 + 自动重启 |

**关键设计：Node 始终只绑回环地址。** 公网入口唯一且必经 Nginx 的 TLS 与限流，
避免出现「Node 直接对外暴露、绕过反代」的配置疏漏。

## 二、架构与安全边界

```
   互联网
     │  HTTPS (443)
     ▼
┌─────────────────────────────┐
│  Nginx                      │  TLS 终止 · 限流 · 安全响应头
│  · /api/login|register      │  登录接口 5 次/分钟（防口令爆破）
│    → 严格限流               │
│  · /healthz                 │  匿名可访问（探活）
│  · 其余 → 10 次/秒          │
└──────────────┬──────────────┘
               │ HTTP (127.0.0.1:8657)
               ▼
┌─────────────────────────────┐
│  Node  server.js            │
│  · 会话校验（HMAC 签名 Cookie）│
│  · 用户隔离（按 userId 分目录）│
│  · ESI 代理（携带用户令牌）  │
└──────────────┬──────────────┘
               ▼
   用户数据/users/<userId>/
     ├─ meta.json      账户 + Client ID
     ├─ auth.json      EVE 令牌
     └─ profiles.json  角色档案
```

### 六层防护

| 层 | 措施 | 位置 |
| --- | --- | --- |
| 传输 | HTTPS + HSTS（可选） | Nginx |
| 入口 | 限流（登录 5/min，普通 10/s） | Nginx |
| 身份 | 用户名 + 口令（scrypt 哈希，每用户独立盐） | `user-store.js` |
| 会话 | HMAC 签名 Cookie（HttpOnly + SameSite=Lax） | `user-store.js` |
| 授权 | 每个请求按 userId 定位存储目录 | `server.js` |
| 运行时 | systemd 沙箱（只允许写 用户数据 目录） | `eve-aux-tool.service` |

### 用户隔离的实现要点

- `userId = SHA256(服务端盐 + 用户名)` → **与口令无关**，改口令不影响目录
- 口令用 **scrypt**（N=16384）哈希，每用户独立随机盐，绝不存明文
- 会话 Cookie 值 = `userId.过期时间.HMAC`，服务端用盐校验签名
- 攻击者无法通过猜测 userId 读取他人文件（路径穿越另有正则防护）
- 旧版单文件（`eve_auth_v1.json` / `eve_char_profiles_v1.json`）首次运行自动迁入 `users/local/`

## 三、部署步骤

### 1. 准备服务器

```bash
# 建议 Ubuntu 22.04 / 24.04，2 核 2G 起
apt update && apt upgrade -y
```

### 2. 执行部署脚本

```bash
# 从源码目录
sudo bash deploy/scripts/deploy.sh
```

脚本会：检查并安装 Node 20 与 Nginx → 创建系统用户 `eve` → 复制文件到 `/opt/eve-aux-tool`
→ 生成 `.env`（权限 600）→ 安装 systemd 服务并启动 → 健康检查。

### 3. 编辑环境变量

```bash
sudo vi /opt/eve-aux-tool/.env
```

必改项：

```ini
BASE_URL=https://eve.example.com          # 外部访问基址
EVE_CLIENT_ID=<欧服 Client ID>
EVE_CLIENT_ID_CN=<国服晨曦 Client ID>       # 国服另需单独注册
EVE_CLIENT_ID_SG=<国服曙光 Client ID>       # 曙光是独立集群，需再单独注册一个
EVE_MULTI_USER=1                          # 多用户（公网必须）
```

> ★ **三套集群的应用互不通用**，必须各注册一个：
> 欧服在 `developers.eveonline.com` 注册，国服在网易开发者后台注册，
> 而**曙光服是独立集群**（独立账号与角色），要单独建应用。
>
> 若让多用户各自在「设置」页按服填写凭据，上面三个变量可以留空 ——
> 此时按「设置」页 → 用户配置 → 环境变量 → 全局兜底的顺序取凭据。

### 4. 配置 Nginx 与证书

```bash
sudo cp /opt/eve-aux-tool/deploy/nginx/eve-aux-tool.conf /etc/nginx/sites-available/
sudo ln -s ../sites-available/eve-aux-tool.conf /etc/nginx/sites-enabled/

# ★ 日志格式与限流区定义（必须一起装）
#   log_format 与 limit_req_zone 只能在 http 段定义，不能写在 server 块里
sudo cp /opt/eve-aux-tool/deploy/nginx/eve-log-format.conf /etc/nginx/conf.d/

sudo nginx -t && sudo systemctl reload nginx

# 申请证书（会自动改写配置）
sudo certbot --nginx -d eve.example.com
```

### 5. 登记 SSO 回调地址

在 EVE 开发者后台把回调地址登记为：

```
https://eve.example.com/sso/callback
```

**国服注意**：需在网易后台单独注册应用，回调地址同样填上面的 HTTPS 地址。
国服公共 client_id（`bc90aa496a404724a93f41b4f4e97761`）绑定的是网易自己的回调页，
本地调试可用，但正式对外服务建议自行注册。

### 6. 开放防火墙

```bash
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
# ★ 不要开放 8657 —— Node 只绑回环，外部访问必须经 Nginx
```

## 四、运维

### 常用命令

```bash
systemctl status eve-aux-tool          # 状态
journalctl -u eve-aux-tool -f          # 实时日志
journalctl -u eve-aux-tool -n 100      # 最近 100 行
systemctl restart eve-aux-tool         # 重启
nginx -t && systemctl reload nginx     # 改完 Nginx 配置
```

### 健康检查

```bash
curl http://127.0.0.1:8657/healthz
# {"ok":true,"service":"eve-aux-tool","version":"0.3.0","uptime":123,"users":5,"mode":"multi-user"}
```

`users` 字段显示已注册用户数，可用于监控异常增长。

### 日志

- **应用日志**：`journalctl -u eve-aux-tool` —— 含真实客户端 IP（依赖 `TRUST_PROXY=1`）
- **访问日志**：`/var/log/nginx/eve-aux-tool.access.log`
- **健康检查请求不记访问日志**（`access_log off`），避免探活刷屏

### 日志轮转

`journalctl` 自带轮转，无需额外配置。若用文件日志，加 `/etc/logrotate.d/eve-aux-tool`：

```
/var/log/nginx/eve-aux-tool.*.log {
    daily
    rotate 14
    compress
    missingok
    notifempty
    sharedmta
    postrotate
}
```

## 五、备份与迁移

### 必须备份的内容

| 路径 | 内容 | 丢了会怎样 |
| --- | --- | --- |
| `/opt/eve-aux-tool/用户数据/users/` | **所有用户的令牌与角色档案** | 用户数据全丢，需重新授权 |
| `/opt/eve-aux-tool/用户数据/server_salt.txt` | 服务端盐 | 已有会话全部失效 |
| `/opt/eve-aux-tool/.env` | Client ID 等配置 | 需重新配置 |

### 备份命令

```bash
sudo tar czf eve-aux-backup-$(date +%Y%m%d).tar.gz \
  -C /opt/eve-aux-tool 用户数据 .env
```

### 迁移到新服务器

```bash
# 1. 复制代码
rsync -av --exclude '用户数据' ./ user@newserver:/opt/eve-aux-tool/

# 2. 恢复数据（★ 必须保留 salt，否则会话失效）
rsync -av user@oldserver:/opt/eve-aux-tool/用户数据/ /opt/eve-aux-tool/用户数据/

# 3. 恢复 .env
scp user@oldserver:/opt/eve-aux-tool/.env newserver:/opt/eve-aux-tool/

# 4. 启动
sudo systemctl restart eve-aux-tool
```

## 七、性能与容量参考

实测（单进程 Node，无 CDN）：

| 指标 | 实测值 |
| --- | --- |
| 首屏加载（数据表 3.7 MB 未压缩） | 约 1.2 s（本地回环） |
| `/healthz` 响应 | < 5 ms |
| ESI 代理单请求 | 取决于上游（实测 0.4–20 s） |
| 内存占用（空载） | 约 60 MB |
| 单用户数据占用 | 约 50 KB |

**优化建议**（按性价比排序）：

1. **开启 gzip** —— 数据表 3.7 MB 可压到 0.69 MB（省 81%），在 Nginx 里配 `gzip on` 即可，
   不需要改代码
2. **数据表长缓存** —— `data/*.json` 变动极少，Nginx 已配 1 小时缓存
3. **ESI 请求缓存** —— `src/data/fetcher.js` 已内置，TTL 可调
4. **多实例横向扩展** —— 用户数据在本地磁盘，多实例需共享存储或按用户粘滞

## 八、已知限制

| 限制 | 说明 |
| --- | --- |
| 无注册频率限制 | 注册接口只靠 Nginx 限流，公网开放注册可能被批量注册刷目录 |
| 无管理员界面 | 用户管理（查看、禁用、删除）目前只能直接操作磁盘文件 |
| 无审计日志 | 谁在何时改了哪个角色档案，未记录 |
| 令牌未加密存储 | `auth.json` 里的 EVE 令牌是明文，依赖文件系统权限保护 |
| 单进程 | 未做多实例的数据一致性设计 |

前四项属于「公共服务化」的待补项，建议在正式对外开放前至少补上**注册频率限制**与
**令牌加密存储**（用 `EVE_SALT` 做 AES-256-GCM 加密，密钥不出服务器）。

## 九、部署配置已在真实 Linux 环境验证（2026-11-03）

> 验证环境：Ubuntu 24.04.5 LTS（WSL2，systemd 已启用）、nginx 1.24.0、Node 18.19.1、
> systemd 255.4。以下每一项都是**实际执行**的结果，不是纸面推演。

### 9.1 systemd 单元文件

```
systemd-analyze verify /etc/systemd/system/eve-aux-tool.service
→ 无输出（通过）
systemctl start eve-aux-tool
→ active (running)，Main PID 499 (node)，内存 49.9M
ss -tlnp | grep 8657
→ LISTEN 127.0.0.1:8657   ← 正确绑定回环，未对外暴露
```

**校验过程中发现并修正的错误**：

| 问题 | 现象 | 修正 |
| --- | --- | --- |
| `StartLimitIntervalSec` 放在 `[Service]` 段 | systemd 报 `Unknown key name` 并**静默忽略** | 移到 `[Unit]` 段 |
| 单元文件带可执行权限 | systemd 报 `is marked executable` | 部署时 `chmod 644` |

### 9.2 Nginx 配置

```
nginx -t
→ syntax is ok / test is successful
```

**校验过程中发现并修正的错误**（三处都会导致 nginx **启动失败**）：

| 问题 | 现象 | 修正 |
| --- | --- | --- |
| `http2 on;` 独立指令 | nginx 1.24 报 `unknown directive "http2"` | 改用 `listen 443 ssl http2;`（1.24 与 1.25.1+ 通用） |
| `log_format` 写在 server 块内 | 报 `"server" directive is not allowed here` 类错误 | 拆到 `deploy/nginx/eve-log-format.conf`，放 `/etc/nginx/conf.d/` |
| `limit_req_zone` 写在 server 块内 | 报 `not allowed here` | 同上，一并移到 conf.d |

> ★ **`log_format` 与 `limit_req_zone` 只能在 `http` 段定义。**
> `sites-enabled` 虽被 include 进 `http` 段，但 `server` 块内部不允许再出现这两类指令。

### 9.3 端到端链路（Node + systemd + Nginx + TLS）

| 验证项 | 结果 |
| --- | --- |
| HTTP → HTTPS 跳转 | `301 → https://test.local/healthz` |
| HTTPS 健康检查（匿名） | `200 {"ok":true,...,"mode":"multi-user"}` |
| HTTPS 受保护接口（未登录） | `401 {"ok":false,"error":"未登录或会话已过期"}` |
| 经反代注册 | `302` + `set-cookie: eve_session=...; HttpOnly; SameSite=Lax` |
| 经反代登录后访问 `/api/profiles` | `200 {"ok":true,"profiles":[]}` |
| 协议协商 | `HTTP/2.0`（`listen ... http2` 生效） |
| 安全响应头 | `x-content-type-options` / `x-frame-options` / `referrer-policy` / `content-security-policy` 全部到位 |
| 访问日志 | `127.0.0.1 - - [...] "GET /api/profiles HTTP/2.0" 200 25 ... rt=0.002`（含真实 IP、协议、耗时） |
| 登录接口限流 | 前 6 次 `401`，第 7、8 次 `429` |
| 优雅关闭 | `systemctl stop` → 日志「收到 SIGTERM，正在关闭…已关闭」 |

### 9.4 ★ 一个隐蔽的部署陷阱

**`EnvironmentFile` 指向的文件不存在时，systemd 会以 `result 'resources'` 失败**，
错误信息完全不提「文件不存在」，排查极易误判为沙箱指令不兼容。

实测排查过程：

```
最小单元（仅 ExecStart）           → active
+ WorkingDirectory                  → active
+ User=root                        → active
+ EnvironmentFile=（文件不存在）     → failed (result 'resources')
```

**处置**：
- 部署脚本会创建 `.env` 并校验其存在
- 单元文件加 `ConditionPathExists=` 前置检查，让缺失时报出可读的错误：

```ini
[Unit]
ConditionPathExists=/opt/eve-aux-tool/.env
```

### 9.5 WSL 与真实服务器的差异

| 项 | WSL2 | 真实服务器 | 注意事项 |
| --- | --- | --- | --- |
| `PrivateTmp=true` | systemd 隔离的 `/tmp` 与宿主不同 | 同 WSL | 测试用的证书放 `/tmp` 会导致 nginx 读不到，须放真实路径 |
| 沙箱指令 | 全部可用（实测通过） | 全部可用 | 无兼容性问题 |
| HTTP/2 | nginx 1.24 需 `listen ... http2` | 同上 | 别用 `http2 on;` |
| systemd | 需在 `wsl.conf` 开启 `[boot] systemd = true` | 默认启用 | — |
